# Model Configuration

AADB includes 15 model definitions. The greenfield installer creates a destination-owned Microsoft Foundry account and deploys GPT-5.6 Luna by default. The web app starts with Luna at medium reasoning. A deployment shows only models whose deployment variables were present when the web image was built.

## Enable Another Supported Model

Adding an already supported model has two steps: deploy the model into the generated Foundry account, then rebuild the web app with its deployment variable. It does not require a Bicep change, full reprovision, or MCP deployment.

1. Check the model/version/SKU catalog and regional quota.
2. Deploy the model in the generated account from `AZURE_AI_ACCOUNT_NAME`.
3. Set its exact deployment name in the selected `azd` environment.
4. Redeploy only the web app.

Example for GPT-5.4 Mini:

```bash
az cognitiveservices account deployment create \
  --resource-group "$(azd env get-value AZURE_RESOURCE_GROUP)" \
  --name "$(azd env get-value AZURE_AI_ACCOUNT_NAME)" \
  --deployment-name "<deployment-name>" \
  --model-name "gpt-5.4-mini" \
  --model-version "<supported-version>" \
  --model-format OpenAI \
  --sku-name GlobalStandard \
  --sku-capacity 10
azd env set AZURE_OPENAI_DEPLOYMENT_GPT54MINI "<deployment-name>"
azd deploy app --no-prompt
```

Set several variables before `azd deploy app` to add several models in one build. After deployment, refresh the app and confirm each model appears in the model selector. Run one representative generation per model; seeing a name in the selector proves only that the deployment variable was built into the UI.

Deployment names are not secrets. The greenfield endpoint is generated by Bicep and the app authenticates with managed identity; no API key is created or stored. Existing browsers retain their selected model in local storage, so adding a model does not change their current selection.

## Verify An Added Model

1. Confirm the intended `azd` environment is selected with `azd env list`.
2. Run `azd deploy app --no-prompt` and require a successful `app` deployment.
3. Open `azd env get-value SERVICE_APP_URL` and refresh the page.
4. Select the added model and generate a small topology.
5. For Blueprint or image import, use a model marked **Yes** in the capability column.

If the model appears but calls fail, check:

- The variable contains the Azure deployment name, not the model catalog name.
- The deployment is reachable through `AZURE_OPENAI_ENDPOINT`.
- The deployment supports the API contract shown above.
- The API key or managed identity has data-plane access to that deployment.
- The selected Azure region has quota for the model.

## Remove A Model

Clear the model's `azd` variable and rebuild the web app:

```bash
azd env set AZURE_OPENAI_DEPLOYMENT_GPT54MINI ""
azd deploy app --no-prompt
```

The model disappears from the selector after the new web revision loads. Browser settings that referenced it fall back to the first configured model.

## Add A New Model Type

A model not listed above is a code change, not just configuration. Update and test all of these surfaces:

- `ModelType`, `MODEL_CONFIG`, and `DEPLOYMENT_NAMES` in `src/stores/modelSettingsStore.ts`.
- API format, reasoning behavior, token budget, structured-output support, and vision support in that model definition.
- Build `ARG` and `ENV` entries in `Dockerfile`.
- The `azd`-to-Vite mapping in `scripts/azd-prepackage.sh`.
- `.env.example` and the GitHub Actions variable mapping.
- Blueprint/image capability behavior in `src/components/AIArchitectureGenerator.tsx` when the API is not the Responses API.
- Generation, validation, deployment-guide, comparison, and malformed-response tests for the new API contract.

Do not classify a model by its marketing family alone. Confirm its actual Azure endpoint shape, request fields, response shape, structured-output behavior, vision support, and token limits before adding it to the registry.

## Bring Your Own Endpoint

Set `deployFoundry` to `false` in `infra/main.parameters.json`, then configure `AZURE_OPENAI_ENDPOINT`, an optional `AZURE_OPENAI_API_KEY`, and supported deployment variables in the selected `azd` environment. When using keyless authentication against an external account, assign the web app identity **Cognitive Services OpenAI User** on that external account before testing.
